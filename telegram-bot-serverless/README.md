# بات مقاله روی Telegram Serverless

نسخهٔ محلی برای انتقال مستقیم **همان بات اصلی** از `../telegram-bot/` است؛ بات آزمایشی لازم نیست.
ساختار با CLI رسمی `@tgcloud/cli@0.2.0` ایجاد شده و کد زمان اجرا فقط در `tgcloud/` قرار دارد.
کد بات اصلی و Workflowهای فعلی تغییر نکرده‌اند.

**مدیریت کلیدها پیاده شده است:** مالک می‌تواند از Mini App کلیدها را در DB داخلی ثبت یا تعویض کند. در این مرحله هیچ migration، Deploy، ورود کلید واقعی یا تست ابری انجام نشده است.

## قابلیت‌ها

- دریافت متن و ویس، تبدیل ویس با مدل `gpt-transcribe` و تأیید موضوع با مهلت ۱۵ دقیقه.
- اجرای `generate-bilingual-article.yml` با همان ورودی `topic` و شاخهٔ `main`.
- ذخیرهٔ درخواست، وضعیت، زمان تأیید، تصمیم انتشار و شناسه‌های Workflow و PR در SQLite داخلی.
- دریافت وضعیت ساخت و لینک PR با دکمهٔ «بررسی وضعیت» یا `/status`.
- تأیید و Merge به روش squash یا رد و بستن PR؛ حذف شاخه در صورت امکان.
- بررسی مالک درخواست، چت، مخزن، Workflow، شاخه و SHA بازبینی‌شده.
- جلوگیری از تکرار عملیات در کلیک هم‌زمان، پیام تکراری و نتیجهٔ نامشخص شبکه.
- صفحهٔ تنظیمات با دو فیلد مخفی و احراز هویت سمت سرور؛ بدون نمایش مقادیر ذخیره‌شده.

بررسی وضعیت فقط با پیام یا کلیک شما اجرا می‌شود؛ اعلان پایان ساخت خودکار اضافه نشده است.
هیچ Polling، حلقهٔ انتظار، زمان‌بندی، Cron یا کار پس‌زمینه‌ای وجود ندارد.
ساخت مقاله، تصویر و Build همچنان در GitHub Actions انجام می‌شوند.

## فایل‌ها

```text
tgcloud/
├── endpoints/
│   ├── credentialsAccess.js # تأیید دسترسی مالک؛ بدون خواندن کلیدها
│   └── saveCredentials.js   # ثبت یا تعویض؛ بدون بازگرداندن مقدار
├── handlers/
│   ├── message.js
│   └── callback_query.js
├── lib/
│   ├── article-bot.js       # جریان مقاله و کنترل دسترسی
│   ├── config.js            # فقط تنظیمات غیرمحرمانهٔ بات اصلی
│   ├── credentials.js       # خواندن و تعویض کلیدها در DB داخلی
│   ├── credentials-endpoints.js # کنترل هویت و ورودی تنظیمات
│   ├── errors.js            # خطاهای عمومی بدون افشای پاسخ سرویس‌ها
│   ├── integrations.js      # OpenAI و GitHub با HTTP خود SDK
│   ├── runtime.js           # اتصال ماژول‌ها به SDK رسمی
│   └── store.js             # ذخیره‌سازی و تغییر اتمی وضعیت
└── schema.js                # جدول‌های article_requests و bot_credentials
mini-app/                    # HTML/CSS/JS مستقل از سایت React
scripts/check.mjs
tests/                       # تست آفلاین با SQLite واقعی و سرویس‌های شبیه‌سازی‌شده
docs/migration.md            # محدودیت‌ها، امنیت و قدم‌های انتقال نهایی
docs/credentials.md          # بازکردن تنظیمات، migration و انتشار
docs/tgcloud-sdk.md          # مرجع SDK تولیدشده توسط CLI رسمی
```

## اجرا و تست آفلاین

از ریشهٔ مخزن:

```bash
cd telegram-bot-serverless
npm ci
npm run check
npm test
npm run status
```

برای ابزارها و تست‌های محلی Node.js نسخهٔ `22.13` یا جدیدتر لازم است؛ تست‌ها از `node:sqlite` و VM Modules استفاده می‌کنند.
این وابستگی‌های Node فقط مربوط به ابزار محلی‌اند و در `tgcloud/` استفاده نشده‌اند.
SDK در محیط تلگرام فراهم می‌شود؛ پکیجی با نام `sdk` از npm نصب نکنید.
تست‌ها هیچ کلید واقعی یا دسترسی شبکه‌ای ندارند.

`status` آفلاین است و تغییرات را نسبت به snapshot محلی CLI نشان می‌دهد؛ سلامت یا وضعیت زندهٔ بات را بررسی نمی‌کند.
`tgcloud run` اجرای ابری است، با ارسال پیام واقعی و دسترسی به دیتابیس؛ در این مرحله اجرا نشده است.

## دستورهای بات

| دستور | کارکرد |
|---|---|
| `/start` | راهنما |
| `/ping` | `بات فعاله ✅` |
| پیام متنی یا ویس | ثبت موضوع و درخواست تأیید |
| `/status` | بررسی آخرین درخواست همین کاربر و چت |
| `/status u123` | بررسی درخواست مشخص |
| `/attach u123 456` | اتصال دستی درخواست با شروع نامشخص به اجرای ۴۵۶، پس از بررسی شما در GitHub |

در دکمه‌های نتیجهٔ مقاله، تأیید به نسخهٔ نمایش‌داده‌شدهٔ PR وابسته است. تغییر محتوا نیاز به بازبینی و تأیید تازه دارد.
موفقیت Merge به معنی تأیید اتمام انتشار لیارا نیست؛ نتیجهٔ Deploy جداست.

## تنظیمات و کلیدها

فقط شناسهٔ کاربر مجاز، مالک مخزن و نام مخزن از تنظیمات بات اصلی به `tgcloud/lib/config.js` منتقل شده‌اند؛ این موارد API Key نیستند.
هیچ توکن Telegram، کلید OpenAI یا GitHub به سورس کپی نشده و هیچ کلید واقعی به دیتابیس وارد نشده است.

طبق تصمیم صریح کاربر، `credentials.js` اکنون از جدول `bot_credentials` می‌خواند؛ اگر کلید موجود نباشد خطای روشن `CREDENTIAL_MISSING` می‌دهد.
ورود و تعویض کلید فقط از endpoint مالک انجام می‌شود؛ هیچ endpoint خواندن کلید وجود ندارد.
روش راه‌اندازی و محدودیت‌های حفاظت در [راهنمای مدیریت کلیدها](docs/credentials.md) آمده است.

کاربر قبلاً پروژه را به بات اصلی متصل کرده است. در این مرحله هیچ اجرای ابری، migration، Deploy، Commit یا Push انجام نشده است.
دستورهای لازم برای ساخت جدول و انتشار، در راهنمای مدیریت کلیدها ثبت شده‌اند و هنوز اجرا نشده‌اند.

مرجع: [مستندات رسمی Telegram Serverless](https://core.telegram.org/bots/serverless).
